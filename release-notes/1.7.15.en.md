BaoCode Codex 1.7.15: a model the server does not know is not named to it

The pick of a conversation can be a model the current server knows
nothing of - one saved from another product, or retired since. Naming it
to the server warns of fallback metadata and can degrade the turn.

Fixed
- When the pick is not a reference to one of your upstreams and the
  server does not list it, what is named to the server is **the server's
  own default model** (which has metadata) - the warning is gone, and
  the turn runs on what the server can do.
- The picker still shows what you picked (Chosen for this
  conversation); your choice is unchanged.
