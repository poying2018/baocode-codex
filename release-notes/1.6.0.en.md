BaoCode Codex: the codex product, on its own

This is the other program: the same source as BaoCode Claude, but a product of
its own. Its own installer, its own folder, its own update channel and its own
links — installing it does not touch the Claude Code one, and the two run side
by side without seeing each other's data.

It brings the Codex CLI with it. OpenAI's CLI travels in the installer (pinned
by version, and checked against the registry's own checksum), so a machine with
no Codex of its own needs neither an install nor a download: the app runs the
one it carries. If you have one of your own — in your PATH, from the npm
package, or the Codex desktop app's — yours is used instead, with your sign-in
and your settings.

New
- The app carries the Codex CLI (0.164.0): nothing to install and nothing to
  download before the first conversation.
- A product of its own in every way: its own installer and uninstall entry,
  its own data folder (%APPDATA%\baocode-codex), its own windows and
  registration, its own links (baocode-codex://), its own Stash folder, its
  own keychain entry, and its own remote-server builds.
- Plan mode: the agent plans with no write access, and Start building carries
  the plan out.

Fixed
- The adapter now speaks the app-server's protocol as it is. Three defects
  could stop a machine from starting at all: a parameter the server does not
  have (which can make it refuse the request outright), a collaboration mode
  that does not exist, and request ids that the server's own numbers could
  collide with — a collision that left a turn waiting for ever.
- What the server reports is used: the reasoning text, MCP server state and
  quota pushes; a command the user declined no longer sits there as running.
- The Stash skill goes into this product's own agent folder, not into Claude
  Code's.
