BaoCode Codex 1.7.1: installed, even where the profile says no

A machine whose profile does not allow the Start Menu folder to be
written, or HKCU\Software\Classes, used to end a setup with nothing
installed at all: the first entry Setup failed to write rolled the whole
installation back. The program goes in now, and the entries that cannot
be written — the shortcuts, the context menu, the baocode link — are left
out, with the reason in the log.

Fixed
- Setup no longer rolls back when the Start Menu folder or the context
  menu and URL scheme cannot be written: the program is installed and
  those are skipped.
- Uninstalling asks what the install asked, so the shortcuts and keys
  that were written are taken away, and the ones that were skipped are
  not looked for.
- The Codex CLI the bundle carries is 0.165.0.
- The changelog on the site carries 1.7.0, which it had been missing.
