BaoCode Codex 1.7.11: a resumed thread no longer names a model this server lacks

Resuming an old thread carries the model of whatever ran it before - a
model of another product, one this server retired, or one of your own
upstreams. Naming it to the current server warns of fallback metadata and
can degrade the turn.

Fixed
- A resumed thread's model is adopted only when the current server lists
  it; otherwise the model you picked stands - the warning is gone, and
  the turn runs on your choice.
