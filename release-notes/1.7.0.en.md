BaoCode Codex 1.7.0: the models are yours to choose

This version puts the models right. The picker used to offer models that
were made up — `gpt-5.5-codex`, `gpt-5.5-mini`, which the server does not
have: a turn asked for one and was refused, which read as the model being
broken. It offers the models the server actually has now — and the upstreams
you configured in Settings → Models appear there too, ready to pick.

New
- The models of your own upstreams appear in the picker, grouped under
  their upstream, as `@deepseek/deepseek-chat` and the like. Picking one
  runs the conversation on it: the endpoint, the key and the protocol are
  given to Codex by the app, and the key travels in the environment rather
  than on a command line.
- Any upstream's protocol works: Codex speaks one protocol (OpenAI's
  Responses), and the app's own local proxy translates for the upstream,
  whatever it speaks.
- A group whose upstream cannot be reached says so, in the picker.

Fixed
- The picker no longer offers models the server does not have.
- The list is asked for as the conversation opens, not only when the first
  message starts the server, so the picker is right the first time.
- The list is kept: what the server listed is shown again at the next start,
  before the server has said anything.
- The model the software passes down is what is in effect — the one in your
  settings, and the one you picked last — instead of being quietly replaced
  by whatever the server's list names first. A pick the server does not list
  is kept and shown rather than silently becoming another model.
